## E. Sequencing risk

- **E1 (M, V).** #71 is Q1, #268 is Q1, and the body says the design *starts by building the as-is map* once #406's format is agreed. #406 is at Development with four questions open. Until they are answered #268 cannot start as the body describes. Either answer them first, or let #268 start from the prose design and draw the map after.
- **E2 (M, I).** #408 (game storage in memory) rewrites `AppState::games` and asks which of memory and database is the source of truth; #71's per-game locking rewrites the same map. #408 says *not gated on it, read each other's diffs*. Two projects designing the same lock is the coordination the project rules exist to avoid. Recommend #71 Core owns the games map and #408 designs its index against `Arc<RwLock<GameSession>>`.
- **E3 (m, V).** `71-impact.md` cuts A to F reuse the letters of WP A to F for different things; the 2026-09-28 review flagged it and it is unchanged.
