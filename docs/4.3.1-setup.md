# Setup

Setting up a development machine, once. Building the production host is in
[4.3.4](4.3.4-production-environment.md#building-a-host); every script is in
[4.3.0 Tools](4.3.0-tools.md).

## Development environment

The dev machine is WSL2 Ubuntu, treated as disposable.

1. **Enable systemd**, which Docker needs. As root, add to `/etc/wsl.conf`:

   ```ini
   [boot]
   systemd=true
   ```

   Then run `wsl --shutdown` in PowerShell and reopen the shell.
2. **Restore the SSH keys** from the Windows-side backup into `~/.ssh`, each
   with its `.pub`. Without a backup, each key is made again and registered
   where it opens.

   | Key | Opens |
   | --- | --- |
   | `id_ed25519_gh` | GitHub, over ssh |
   | `oracle_tile_lite_elite` | production |
   | `oracle_tile_lite_elite_rehearsal` | rehearsal |

3. **Clone both repositories** side by side, with the GitHub key:

   ```bash
   export GIT_SSH_COMMAND='ssh -i ~/.ssh/id_ed25519_gh'
   git clone git@github.com:delphside/tile-lite-elite.git
   git clone git@github.com:delphside/programme.git
   unset GIT_SSH_COMMAND
   ```

4. **Run the setup script** from `tile-lite-elite`:
   `./scripts/develop/setup-dev-environment.sh`.
5. **Open a new shell**, so the `docker` group applies, and run `sshkeys` to
   load the keys into the agent. Run `sshkeys` once after each boot.
6. **Verify.** Each command exits 0:

   ```bash
   cargo test --workspace
   dx --version         # 0.6.3, the version the setup script pins
   docker compose version
   bats --version
   ssh tile-lite-elite echo ok
   ssh tile-lite-elite-rehearsal echo ok
   ```

The setup script is idempotent. It installs:

- the Rust toolchain in `rust-toolchain.toml`, with the
  `wasm32-unknown-unknown` target;
- `dioxus-cli` at the version the script pins, and `wasm-bindgen-cli` at the
  version in `Cargo.lock`;
- `sccache`, bats with bats-support and bats-assert, and the desktop client's
  system libraries;
- Docker Engine, with its build cache capped at 20 GB. Under WSL, Docker sizes
  its limit from the WSL virtual disk, and without a cap it kept 305 GB.

It also writes:

- `~/.ssh/config` entries for the three keys, and an ssh-agent at a fixed
  socket in `~/.bashrc`, with `sshkeys` to load it;
- `core.sshCommand` in the global git config, so git reaches that agent;
- the shell shortcuts `sadev`, `sapre`, `dbdev`, `dbpre` and `dbprod`
  ([4.3.0](4.3.0-tools.md));
- `core.hooksPath`, set to `.githooks`;
- the `programme/` submodule, by `git submodule update --init`.

### The two copies of the programme

| Copy | Path | Holds | Updated by |
| --- | --- | --- | --- |
| *live checkout* | `../programme`, or `PROGRAMME_DIR` | the records the scripts read and write | `git pull` in it |
| submodule | `programme/` | the generic documents, rules, skills and agents, at a pinned commit; `.claude/skills` and `.claude/agents` link into it | `git submodule update --init`, after a pull that moves the pin |

## Cloud sessions

A Claude Code session on the web starts in a VM that has Rust, Node 22, Docker
and a Chromium for Playwright. Two scripts add the rest. The owner pastes the
first into the cloud environment's settings.

| Script | Runs | Does |
| --- | --- | --- |
| the programme's [`.claude/cloud-environment-setup.sh`](https://github.com/delphside/programme/blob/main/.claude/cloud-environment-setup.sh) | at environment build, cached about seven days | installs the desktop client's libraries; writes the SessionStart hook that runs each repository's `cloud-setup.sh` |
| [`.claude/cloud-setup.sh`](../.claude/cloud-setup.sh) | at every session start, where `CLAUDE_CODE_REMOTE` is `true` | the steps in the following list |

`cloud-setup.sh`:

- installs the pinned toolchain and Wasm target, prebuilt `dx` and
  `wasm-bindgen` at the `Cargo.lock` versions, bats, `sqlite3` and
  `e2e/node_modules`;
- empties `RUSTC_WRAPPER`, because `.cargo/config.toml` names the dev machine's
  sccache;
- sets `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to the VM's Chromium, because the cloud
  network refuses Playwright's own browser download;
- initialises the `programme/` submodule and sets `core.hooksPath`.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| the web build hangs | sccache on the Wasm target | build with `RUSTC_WRAPPER=""`, as `scripts/develop/services.sh` does ([4.3.2](4.3.2-development.md)) |
| the client builds but does not run, or `wasm-bindgen` reports a schema mismatch | `wasm-bindgen-cli` differs from the `wasm-bindgen` crate in `Cargo.lock` | run the setup script again, which installs the locked version |
