## Development environment

The development machine is WSL2 Ubuntu, treated as disposable.

1. **Install Ubuntu with the user `steve`**, because `.cargo/config.toml`
   names `/home/steve/.cargo/bin/sccache` as the compiler wrapper.
2. **Enable systemd**, which Docker needs. As root, add to `/etc/wsl.conf`:

   ```ini
   [boot]
   systemd=true
   ```

   Then, in PowerShell:

   ```powershell
   wsl --shutdown
   ```

   Reopen the Ubuntu shell.
3. **Restore the SSH keys** from the owner's Windows-side backup into `~/.ssh`,
   each with its `.pub`, and tighten their permissions, which a copy from
   Windows loosens:

   ```bash
   chmod 600 ~/.ssh/id_ed25519_gh ~/.ssh/oracle_tile_lite_elite*
   chmod 644 ~/.ssh/*.pub
   ```

   | Key | Opens |
   | --- | --- |
   | `id_ed25519_gh` | GitHub, over SSH |
   | `oracle_tile_lite_elite` | production |
   | `oracle_tile_lite_elite_rehearsal` | rehearsal |

   Without a backup, the owner makes new keys under the same names, adds the
   GitHub one to GitHub and gives each host its new public key through the
   cloud provider's console, where the original was added
   ([4.3.4](4.3.4-production-environment.md#building-a-host)).
4. **Clone both repositories** into `~/tile-lite-elite`, with the GitHub key:

   ```bash
   mkdir -p ~/tile-lite-elite && cd ~/tile-lite-elite
   export GIT_SSH_COMMAND='ssh -i ~/.ssh/id_ed25519_gh'
   git clone git@github.com:delphside/tile-lite-elite.git main
   git clone git@github.com:delphside/programme.git programme
   unset GIT_SSH_COMMAND
   ```

5. **Run the setup script** from `~/tile-lite-elite/main`, as yourself and
   not under `sudo`; it calls `sudo` where it needs to:

   ```bash
   ./scripts/develop/setup-dev-environment.sh
   ```

   Skip the manual steps its closing message lists: they are this page's
   steps 3, 7 and 8.
6. **Install what the script leaves out**:

   - `sqlite3`: `dbdev`, the browser tests' clean-up and the backup tests;
   - Node 22, CI's version: the browser tests
     ([4.3.2](4.3.2-development.md#end-to-end-ui-tests-playwright)).

   ```bash
   sudo apt-get install -y sqlite3
   curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
   sudo apt-get install -y nodejs
   ```

7. **Open a new shell**, so the `docker` group applies, and load the keys into
   the agent. Run this once after each boot:

   ```bash
   sshkeys
   ```

8. **Verify.** Each command exits 0:

   ```bash
   cargo test --workspace
   dx --version         # the version setup-dev-environment.sh pins
   docker compose version
   bats --version
   sqlite3 --version
   node --version       # v22
   ssh tile-lite-elite echo ok
   ssh tile-lite-elite-rehearsal echo ok
   ```

The setup script is idempotent. What it installs and writes:

| What | Where |
| --- | --- |
| the Rust toolchain in `rust-toolchain.toml`, with the `wasm32-unknown-unknown` target | `~/.rustup` |
| `dioxus-cli` at the version the script pins, `wasm-bindgen-cli` at the version in `Cargo.lock` | `~/.cargo/bin` |
| `sccache` | `~/.cargo/bin` |
| build tools (`build-essential`, `pkg-config`, `libssl-dev`); bats with bats-support and bats-assert; the desktop client's system libraries | apt |
| Docker Engine, its build cache capped at 20 GB (the default, sized from WSL's virtual disk, let it reach 305 GB) | apt; the cap in `/etc/docker/daemon.json` |
| host entries for the three keys | `~/.ssh/config` |
| an `ssh-agent` at a fixed socket, the `sshkeys` alias, and the shell shortcuts `sadev`, `sapre`, `dbdev`, `dbpre` and `dbprod` ([admin CLI](4.3.4-production-environment.md#admin-cli), [database](4.3.4-production-environment.md#inspecting-the-database)) | `~/.bashrc` |
| `core.sshCommand`, so git reaches that agent | the global git config |
| `core.hooksPath` set to `.githooks`, and the `programme/` submodule initialised | the clone |
| a check of the [live checkout](#the-two-copies-of-the-programme), warning when it is missing, not a git checkout or behind `origin/main` | prints only |

### The two copies of the programme

| Copy | Path | Holds | Updated by |
| --- | --- | --- | --- |
| *live checkout* | `../programme`, or the path in the environment variable `PROGRAMME_DIR` | the records the scripts read and write | `git pull` in it |
| submodule | `programme/` | the generic documents, rules, skills and agents, at a pinned commit; `.claude/skills` and `.claude/agents` link into it | `git submodule update --init`, after a pull that moves the pin |

## Cloud sessions

A Claude Code session on the web starts in a VM that has Rust, Node 22, Docker
and a Chromium for Playwright. Two scripts add the rest:

| Script | Who runs it, and when | Does |
| --- | --- | --- |
| the programme's `.claude/cloud-environment-setup.sh` ([1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#claudes-tooling)) | the owner pastes it into the cloud environment's settings; it runs when the environment is built, and the build is cached | installs the desktop client's libraries, and writes the user-level hook that runs `cloud-setup.sh` |
| [`.claude/cloud-setup.sh`](../.claude/cloud-setup.sh) | that hook, at each session start and resume, where `CLAUDE_CODE_REMOTE` is `true` | installs the pinned toolchain and Wasm target, prebuilt `dx` and `wasm-bindgen` at the `Cargo.lock` versions, bats, `sqlite3` and `e2e/node_modules`; empties `RUSTC_WRAPPER` (`.cargo/config.toml` names the development machine's sccache); points `PLAYWRIGHT_CHROMIUM_EXECUTABLE` at the VM's Chromium (the cloud network refuses Playwright's download); initialises the submodule and sets `core.hooksPath` |

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| the web build hangs | sccache ([4.3.2](4.3.2-development.md#manual-web-client)) | build with `RUSTC_WRAPPER=""` |
| the client builds but does not run, or `wasm-bindgen` reports a schema mismatch | `wasm-bindgen-cli` differs from the `wasm-bindgen` crate in `Cargo.lock` | run the setup script again, or start a new cloud session; each installs the locked version |
