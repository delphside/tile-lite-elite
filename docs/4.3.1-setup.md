# Setup

Setting up the owner's development machine, once. Building the production
host is in [4.3.4](4.3.4-production-environment.md#building-a-host); the
scripts are registered in [4.3.0 Tools](4.3.0-tools.md).

## Development environment

The development machine is WSL2 Ubuntu, treated as disposable, and its user is
`steve`: `.cargo/config.toml` names `/home/steve/.cargo/bin/sccache` as the
compiler wrapper, so a build under another user fails until that line changes.

1. **Enable systemd**, which Docker needs. As root, add to `/etc/wsl.conf`:

   ```ini
   [boot]
   systemd=true
   ```

   Then, in PowerShell:

   ```powershell
   wsl --shutdown
   ```

   Reopen the Ubuntu shell.
2. **Restore the SSH keys** from the owner's Windows-side backup into `~/.ssh`,
   each with its `.pub`, and tighten their permissions, which a copy from
   Windows loosens:

   ```bash
   chmod 600 ~/.ssh/id_ed25519_gh ~/.ssh/oracle_tile_lite_elite*
   chmod 644 ~/.ssh/*.pub
   ```

   | Key | Opens |
   | --- | --- |
   | `id_ed25519_gh` | GitHub, over SSH |
   | `oracle_tile_lite_elite` | production |
   | `oracle_tile_lite_elite_rehearsal` | rehearsal |

   Without a backup, the owner makes new keys and adds each public key to
   GitHub or to the host's `~/.ssh/authorized_keys`.
3. **Clone both repositories** side by side, with the GitHub key:

   ```bash
   export GIT_SSH_COMMAND='ssh -i ~/.ssh/id_ed25519_gh'
   git clone git@github.com:delphside/tile-lite-elite.git
   git clone git@github.com:delphside/programme.git
   unset GIT_SSH_COMMAND
   ```

4. **Run the setup script** from `tile-lite-elite`, as yourself and not under
   `sudo`; it calls `sudo` where it needs to:

   ```bash
   ./scripts/develop/setup-dev-environment.sh
   ```

   Its closing message predates these steps; continue with step 5.
5. **Install what the script leaves out**: `sqlite3`, which `dbdev` needs, and
   Node 22, the version CI uses, for the browser tests
   ([4.3.2](4.3.2-development.md#end-to-end-ui-tests-playwright)):

   ```bash
   sudo apt-get install -y sqlite3
   ```

   Node 22 comes from NodeSource or `nvm`.
6. **Open a new shell**, so the `docker` group applies, and load the keys into
   the agent. Run this once after each boot:

   ```bash
   sshkeys
   ```

7. **Verify.** Each command exits 0:

   ```bash
   cargo test --workspace
   dx --version         # the version setup-dev-environment.sh pins
   docker compose version
   bats --version
   node --version       # v22
   ssh tile-lite-elite echo ok
   ssh tile-lite-elite-rehearsal echo ok
   ```

The setup script is idempotent. What it installs and writes:

| What | Where |
| --- | --- |
| The Rust toolchain in `rust-toolchain.toml`, with the `wasm32-unknown-unknown` target | rustup |
| `dioxus-cli` at the version the script pins, `wasm-bindgen-cli` at the version in `Cargo.lock` | `~/.cargo/bin` |
| `sccache`; bats with bats-support and bats-assert; the desktop client's system libraries | system packages and `~/.cargo/bin` |
| Docker Engine, its build cache capped at 20 GB: under WSL, Docker sizes its limit from the WSL virtual disk, and without a cap it kept 305 GB | `/etc/docker/daemon.json` |
| Host entries for the three keys | `~/.ssh/config` |
| An `ssh-agent` at a fixed socket, the `sshkeys` alias, and the shell shortcuts `sadev`, `sapre`, `dbdev`, `dbpre` and `dbprod` ([4.3.4](4.3.4-production-environment.md#inspecting-the-database)) | `~/.bashrc` |
| `core.sshCommand`, so git reaches that agent | the global git config |
| `core.hooksPath` set to `.githooks`, and the `programme/` submodule initialised | the clone |

It also checks the live checkout, and warns when it is missing, not on `main`
or behind.

### The two copies of the programme

| Copy | Path | Holds | Updated by |
| --- | --- | --- | --- |
| *live checkout* | `../programme`, or the path in the environment variable `PROGRAMME_DIR` | the records the scripts read and write | `git pull` in it |
| submodule | `programme/` | the generic documents, rules, skills and agents, at a pinned commit; `.claude/skills` and `.claude/agents` link into it | `git submodule update --init`, after a pull that moves the pin |

## Cloud sessions

A Claude Code session on the web starts in a VM that has Rust, Node 22, Docker
and a Chromium for Playwright. Two scripts add the rest:

| Script | Who runs it, and when | Does |
| --- | --- | --- |
| the programme's `.claude/cloud-environment-setup.sh` ([1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#claudes-tooling)) | the owner pastes it into the cloud environment's settings; it runs when the environment is built, and the build is cached | for this application, installs the desktop client's libraries |
| [`.claude/cloud-setup.sh`](../.claude/cloud-setup.sh) | the SessionStart hook, at each session start where `CLAUDE_CODE_REMOTE` is `true` | installs the pinned toolchain and Wasm target, prebuilt `dx` and `wasm-bindgen` at the `Cargo.lock` versions, bats, `sqlite3` and `e2e/node_modules`; empties `RUSTC_WRAPPER`; sets `PLAYWRIGHT_CHROMIUM_EXECUTABLE`; initialises the submodule and sets `core.hooksPath` |

`RUSTC_WRAPPER` is emptied because `.cargo/config.toml` names the development
machine's sccache. `PLAYWRIGHT_CHROMIUM_EXECUTABLE` points at the VM's Chromium
because the cloud network refuses Playwright's own browser download.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| the web build hangs | sccache on the Wasm target | build with `RUSTC_WRAPPER=""` ([4.3.2](4.3.2-development.md#manual-web-client)) |
| the client builds but does not run, or `wasm-bindgen` reports a schema mismatch | `wasm-bindgen-cli` differs from the `wasm-bindgen` crate in `Cargo.lock` | run the setup script again, which installs the locked version |
