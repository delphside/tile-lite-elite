# Word lists and dictionaries

How a word list becomes the dictionary the engine searches, and how to redo it.

Four dictionaries ship: `sowpods`, `enable2k`, `german` and `spanish`. Each is
built from its own committed list in `crates/rules-shared/src/`. Three files in
`crates/rules-shared/src/wordlists/` decide what nobody may play and what no
engine will choose: `denylist.txt`, `greylist.txt` and `greylist-stems.txt`.
What each is for, and why the denylist is narrow, is in
[`wordlists/README.md`](../crates/rules-shared/src/wordlists/README.md). This
page covers how the lists are produced, verified and changed.

## From upstream to dictionary

```mermaid
flowchart LR
    U["upstream file<br/>(.gz / .json / plain)"] -->|extract| P["words.txt<br/>one word per line"]
    P -->|normalise| C["committed list<br/>crates/rules-shared/src/&lt;dictionary&gt;.txt"]
    D["denylist.txt"] -->|remove| C
    C -->|build at startup| T["TieredDictionary<br/>in memory"]
    G["greylist.txt"] -->|consulted at play| E["GreedyEngine"]
```

## Stage 1: recording where a list came from

[`ATTRIBUTIONS.md`](../ATTRIBUTIONS.md) holds one entry per list:

- upstream URL;
- SHA-256 of the upstream file as fetched;
- licence;
- counts read in and written out.

CI checks a committed list's properties
([stage 5](#stage-5-verifying-a-list)). It cannot check that the list came
from the stated upstream, so a green build is no proof of provenance. The
owner holds the upstream file and compares its checksum with the recorded one,
as a step of the
[re-sourcing runbook](#runbook-re-sourcing-a-list).

## Stage 2: extracting plain text

Extraction is the only per-source step and is done by hand in shell: each
upstream has its own container, and the importer reads plain text. The output
is `words.txt`, one word per line, in any letter case. Upstream layouts move,
so check the URL in `ATTRIBUTIONS.md` first.

| Dictionary | Upstream file (raw URL) | Shape |
| --- | --- | --- |
| `enable2k` | `https://raw.githubusercontent.com/BartMassey/wordlists/master/enable2k.txt.gz` | gzipped text |
| `german` | `https://raw.githubusercontent.com/enz/german-wordlist/master/words` | plain text |
| `spanish` | `https://raw.githubusercontent.com/words/an-array-of-spanish-words/master/index.json` | JSON array |
| `sowpods` | `https://raw.githubusercontent.com/jesstess/Scrabble/master/scrabble/sowpods.txt` | plain text, from a mirror |

Fetch the file to disk, take its checksum, then extract:

```bash
curl -sLo upstream <raw URL>
sha256sum upstream
gunzip -c upstream > words.txt          # enable2k
cp upstream words.txt                   # german, sowpods
jq -r '.[]' upstream > words.txt        # spanish
```

## Stage 3: normalising a list

`normalise(text, &alphabet)` in `crates/rules-shared/src/wordlists.rs`, run by
`import-wordlist`. In order:

1. trim and uppercase each line; the board holds uppercase graphemes, and
   Unicode uppercases `ß` to `SS`, which is how German sets play it (no `ß`
   tile), so there is no special case;
2. drop a word with a character outside the dictionary's alphabet
   (`VariantRules::alphabet`; Spanish has `Ñ` and no `K` or `W`, German adds
   `Ä Ö Ü`); the test is per character, so Spanish `C`, `H`, `L` and `R` all
   pass and the `CH`, `LL` and `RR` tiles need no handling;
3. drop a word shorter than 2 or longer than 15 characters; 15 is the board
   width and 2 the shortest play;
4. sort and dedupe in byte (code-point) order; a locale-aware sort files
   German `Ä` beside `A` and fails the fixed-point test below;
5. end the output with one newline.

`remove_denied` (`--remove-denied`) is a separate step, committed separately.
The history then shows where a list first departs from its upstream. When the
denylist is not empty it returns the lines joined without a final newline, so
its output fails the fixed-point test until the newline is added back (the
[denylist runbook](#runbook-changing-the-denylist) does).

### The fixed-point test

A committed list must equal `normalise` of itself. The test is
`every_word_list_is_a_fixed_point_of_the_normaliser` in
`crates/rules-shared/src/dictionary.rs`, and it fails on:

- a changed alphabet;
- a changed length bound;
- a list edited, or imported without normalising, including a missing final
  newline.

It proves a list is normalised, with no second copy of the rules to drift.
Startup does not depend on it: `TieredDictionary::from_word_list` filters the
words against the alphabet again, and `from_encoded` sorts them by letter index
and dedupes, so file order affects no lookup.

## Stage 4: the greylist and the denylist

The owner curates the denylist, because what a person may play is a game rule.
The greylist is generated. A wrongly denied word is taken from a person, who
notices. A wrongly greyed word is one the engine declines, which nobody
notices.

[`rustrict`](https://crates.io/crates/rustrict) cannot generate the denylist
at any threshold. It is a chat moderator built to defeat evasion, so on
isolated words it fires on stems and topics: `OFFENSIVE | SEVERE` flags
`HOLOCAUST`, `JEW`, `QUEER` and `SCUNTHORPE`. The
[README](../crates/rules-shared/src/wordlists/README.md) has the
measurements.

### Generating the greylist

`generate-greylist` writes `greylist.txt` from the committed `sowpods.txt` and
`enable2k.txt` together:

```text
greylist = rustrict is(Type::ANY) on the lowercased word
         ∪ words matching an entry in greylist-stems.txt
         − exclusions in greylist-stems.txt
         − denylist
```

- **rustrict** is a dependency of `wordlist-tools` only, pinned exactly in its
  `Cargo.toml` and recorded in `ATTRIBUTIONS.md`; the server and the wasm
  client do not link it. The generator lowercases each word because an
  all-caps string can raise `SPAM` on its own.
- **The count** is in the header of `greylist.txt`.
- **Stems** cover rustrict's arbitrary recall gaps: it flags `NEGROES` and not
  `NEGRO`, `POOFTER` and not `POOF`, and misses `MONG`. The syntax is in the
  header of `greylist-stems.txt`.
- **Prefix stems** are reviewed per stem, not applied as a blanket substring
  pass. `NEGRO*` excludes `NEGRONI`; `MONG*` would catch `MONGER` and
  `MONGOOSE`, so `MONG` is exact.
- **Plurals:** a one-off sweep added the 93 plurals of greylisted bases found
  in the dictionaries, in the plurals section of `greylist-stems.txt`. A
  plural the sweep missed, or one whose base was added later, is not
  greylisted, and an engine may play it.
- **List length** costs little: `GreedyEngine` tests a move against the
  greylist only when the move would become the best so far, and a stem leans
  towards greying.
- **The report** on stderr lists exact stems found in no dictionary and
  exclusions that match no prefix stem.

### Curating the denylist

`denylist.txt` is empty. The candidate set is rustrict's `OFFENSIVE & SEVERE`
intersection plus the slurs the
[LDNOOBW list](https://github.com/LDNOOBW/List-of-Dirty-Naughty-Obscene-and-Otherwise-Bad-Words)
catches and rustrict misses (`NEGRO`, `MONG`, `POOF`, `POON`). rustrict
proposes and the owner strikes the false positives. A struck word that rustrict
or a stem flags still reaches the greylist. The two lists cover English only,
because nobody on the project can review German or Spanish.

## Stage 5: verifying a list

`cargo test -p rules-shared` and `cargo test -p engine-core` run these, and CI
runs them ([4.3.3](4.3.3-testing-ci-and-release.md#23-continuous-integration)):

| Test | Proves |
| --- | --- |
| `every_word_list_is_a_fixed_point_of_the_normaliser` | each list is in normalised form |
| `no_committed_word_list_holds_a_denied_word` | the lists were re-imported after a denylist change |
| `matching_is_whole_word_never_substring` | `SCUNTHORPE`, `ASSASSIN` and `BASEMENT` survive a denylist of their substrings |
| `the_greylist_ships_populated_and_the_denylist_empty` | the shipped state; an empty denylist removes nothing |
| `stem_expansion_does_not_catch_ordinary_words` | the listed ordinary words stay ungreyed |
| `the_base_words_rustrict_misses_are_greylisted` | the stems close rustrict's gaps |
| `crates/rules-shared/tests/greylist_plurals.rs` | sampled plurals stay greylisted and ordinary words stay playable |
| `the_bot_declines_a_greylisted_word_that_would_have_won` | the engine avoids the real greylist |

## Stage 6: using the lists at run time

- **Dictionary:** `TieredDictionary::from_word_list(text, &alphabet)` builds
  each dictionary once, behind a `LazyLock`; `build_all_dictionaries()` warms
  them off the request path. The structure is in
  [4.2.1](4.2.1-rules-engine.md#dictionary-structure).
- **Greylist:** not part of the dictionary. `GreedyEngine` asks
  `is_avoided_by_engines` of the main word and every cross word of a move,
  only for a move that beats the best so far. The function is true for a word
  on either the greylist or the denylist.
- **Denied words:** gone from the committed lists, so a player gets the
  ordinary not-in-the-dictionary message.

## Runbook: re-sourcing a list

1. Fetch the upstream file, record its SHA-256 and extract `words.txt`
   ([stage 2](#stage-2-extracting-plain-text)).
2. **Owner:** compare the checksum with the `ATTRIBUTIONS.md` entry and read
   the upstream licence. A new checksum means upstream moved.
3. Import. Counts go to stderr and the list to stdout:

   ```bash
   cargo run --release -p wordlist-tools --bin import-wordlist -- <name> \
     < words.txt > crates/rules-shared/src/<name>.txt
   ```

4. Run `cargo test -p rules-shared`; the fixed-point test is the acceptance
   check.
5. Update the dictionary's `ATTRIBUTIONS.md` entry: URL, licence, checksum,
   counts.
6. Commit the list and the attribution together.
7. If the denylist is not empty, run its re-import
   ([step 3 of the denylist runbook](#runbook-changing-the-denylist)) for this
   dictionary and commit that on its own.
8. For `sowpods` and `enable2k`, regenerate the greylist, because the
   generator reads the committed lists
   ([greylist runbook](#runbook-changing-the-greylist), from step 2).

## Runbook: changing the greylist

1. Edit `greylist-stems.txt`, never `greylist.txt`.
2. Generate:

   ```bash
   cargo run --release -p wordlist-tools --bin generate-greylist \
     > crates/rules-shared/src/wordlists/greylist.txt
   ```

3. Read the report on stderr. For each unknown exact stem, fix the typo. For
   each idle exclusion, fix it or drop it.
4. Run `cargo test -p rules-shared -p engine-core`.
5. Record the count (in the header of `greylist.txt`) and the rustrict version
   in the greylist section of `ATTRIBUTIONS.md`.
6. Commit the stems, the greylist and `ATTRIBUTIONS.md` together.

Regenerate the same way, from step 2, after re-sourcing `sowpods` or `enable2k`
or changing the denylist: the generator reads the committed lists and the
denylist.

## Runbook: changing the denylist

1. **Owner:** decide the words, from the candidate set
   ([stage 4](#curating-the-denylist)). Edit `denylist.txt`.
2. Re-import all four lists, because the denylist applies to every dictionary
   and `no_committed_word_list_holds_a_denied_word` checks all four. German
   and Spanish are re-imported although the denylist holds English: a denied
   word may also be a German or Spanish word.
3. Re-import each list from its committed text, through a temporary file
   (redirecting into the file being read empties it). `remove_denied` drops the
   final newline, so the loop adds it back:

   ```bash
   for name in sowpods enable2k german spanish; do
     list=crates/rules-shared/src/$name.txt
     tmp=$(mktemp)
     cargo run --release -p wordlist-tools --bin import-wordlist -- \
       "$name" --remove-denied < "$list" > "$tmp" \
       && echo >> "$tmp" && mv "$tmp" "$list"
   done
   ```

4. Regenerate the greylist ([greylist runbook](#runbook-changing-the-greylist),
   from step 2).
5. Update `the_greylist_ships_populated_and_the_denylist_empty` to the new
   shipped state, then run `cargo test -p rules-shared -p engine-core`.
6. Commit the denylist, the four lists and the greylist together. The diff over
   the lists is the record of what was removed.

## Not automated

| What | Who | Why |
| --- | --- | --- |
| extraction | Claude | one line of shell per source |
| provenance check | owner | needs the network and an upstream file that may have moved |
| denylist curation | owner | a judgement no classifier makes |
| greylist stem review | owner | a stem that widens onto an ordinary word costs the engine vocabulary |
