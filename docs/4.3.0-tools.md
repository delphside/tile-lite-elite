## The application's tooling

**It lives in `scripts/`, in four folders** that follow the workstreams that own
them. A script is here if it acts on the application and the environments it runs
in; the programme's are in the `programme/` submodule
([1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#two-kinds-of-tooling)),
and `scripts/tests/` holds this repository's tests. The folders are the technical
profile's `scripts.groups`, which is where the pre-commit hook reads them.

| folder | holds | owned by ([workstreams](https://github.com/delphside/programme/blob/main/applications/tile-lite-elite/3.1.4-workstreams.md)) |
| --- | --- | --- |
| `develop/` | building and running the application on a development machine, and the checks of its own code and documents that `check-docs.sh` runs | Delivery Tooling |
| `deliver/` | preview, rehearsal and production together: deploying, rolling back, verifying, and the gates and libraries they share | Delivery Tooling |
| `operate/` | the live system: backups, host checks, the log-hygiene job, and `systemd/`, the timers that run them | Operations & Infrastructure |
| `measure/` | benchmarks, the checks of the running server's limits, and the comment inventory | Capacity Planning |

**A change here takes a project and a branch**, and is tried on preview or
rehearsal before it merges, because `main` is where every script is run from. The
pre-commit hook warns, and does not refuse, when a commit to `main` touches one of
these folders, since a typo needs no branch. **A script finds the repository from
its own path**, so a script gains a level of `..` for each folder it sits in
(`scripts/<folder>/x.sh` is two below the root), and one that calls a script in another
folder says so (`../deliver/run-log.sh`). **A new script is registered below**, in
the table of the folder it is in.

## Examples

**`crates/*/examples/` is not registered**, and that is deliberate rather than
a backlog. An example demonstrates, measures or reproduces; it is not something
you are expected to find here and run. Three of them write a results CSV that is
committed, which is fine — what an example must never do is produce something
compiled into the binary. That is the line, and it is the same line
`programme/.githooks/pre-commit` draws when it excludes `examples/` from the rule that an
image change takes a branch: anything generating a file the binary
