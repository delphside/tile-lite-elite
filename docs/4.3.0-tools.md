## The application's tooling

The scripts are in the four folders `app-profile.toml` lists as `scripts.groups`,
and their tests in `scripts/tests/`
([1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#two-kinds-of-tooling)).

| Folder | Holds |
| --- | --- |
| `develop/` | building and running the application on a development machine, and the checks of its own code and documents that `check-docs.sh` ([1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#the-documents)) runs |
| `deliver/` | preview, rehearsal and production together: deploying, rolling back, verifying, and the gates and libraries they share |
| `operate/` | the live system: backups, host checks, the log-hygiene job and `systemd/`, the timers that run them |
| `measure/` | benchmarks, the checks of the running server's limits and the comment inventory |
| `tests/` (`scripts/tests/`) | this repository's tests of the tooling |

Rules for a script here:

- change it as
  [1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#two-kinds-of-tooling)
  says for the application's tooling, except what is installed on the
  production host, which is a Production Release that the owner copies there
  ([the production host](https://github.com/delphside/programme/blob/main/applications/tile-lite-elite/3.1.2-artefacts.md#the-production-host))
- reach the repository root from the script's own path (two levels up from
  `scripts/<folder>/`), and another folder's script by a relative path
  (`../deliver/run-log.sh`)

**Whoever adds a tool adds its row:**

| Where the new tool is | Its row goes in | The pre-commit hook refuses it unregistered |
| --- | --- | --- |
| an executable in `scripts/<folder>/` | that folder's table | yes |
| a sourced, non-executable script in `scripts/<folder>/` | that folder's table | no |
| a `.sh` or `.py` at the top of `scripts/` | the table of its activity | yes |
| `.githooks/*`, `.claude/*.sh` | *Repository and session* | yes |
| a skill or agent | the programme's [1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#claudes-tooling); written in the programme and linked into `.claude/` | a backstop: only a skill folder made in this repository |
| application CI in `.github/` (`ci.yml`, `advisories.yml`, `dependabot.yml`) | *Deliver* | no |
| any other workflow in `.github/` | the programme's [1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md) | no |
| `e2e/`, a Cargo binary or an example a document tells the reader to run | the table of the activity it serves | no |

The pre-commit hook (the `.githooks/pre-commit` row of
[1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#the-board))
checks the kinds marked *yes*:

- it refuses a commit that adds a file of such a kind unless the file's name (a
  skill's folder name) is in this page or in
  [1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md)
- it reads 1.1 as pinned in the submodule: a name added to 1.1 on the
  programme's `main` counts once the pin moves
- it skips a file already tracked and a file in `scripts/tests/`
