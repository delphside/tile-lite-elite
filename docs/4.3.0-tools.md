The programme's tools, and the rule that tells the two kinds apart, are in
[1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#two-kinds-of-tooling). What the tools touch (environment
variables, volumes, ports) is in [4.4.1](4.4.1-configuration.md).

## The application's tooling

The scripts are in `scripts/`, in four folders that follow the workstreams that
own them, and `scripts/tests/` holds the tests. The folders are the
`scripts.groups` of `programme.toml`, the technical profile
([1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#the-board)), which the pre-commit hook reads. Which workstream owns
which file is in
[3.1.4](https://github.com/delphside/programme/blob/main/applications/tile-lite-elite/3.1.4-workstreams.md).

| Folder | Holds |
| --- | --- |
| `develop/` | building and running the application on a development machine, and the checks of its own code and documents that `check-docs.sh` runs |
| `deliver/` | preview, rehearsal and production together: deploying, rolling back, verifying, and the gates and libraries they share |
| `operate/` | the live system: backups, host checks, the log-hygiene job and `systemd/`, the timers that run them |
| `measure/` | benchmarks, the checks of the running server's limits and the comment inventory |
| `tests/` | this repository's tests of the tooling |

Rules for a script here:

- change it on a project's branch, and try it on preview or rehearsal first
  ([1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#two-kinds-of-tooling)); the pre-commit hook only warns when a
  commit to `main` touches one of these folders
- find the repository from the script's own path, so it gains a `..` for each
  folder it sits in (`scripts/<folder>/x.sh` is two below the root); a script
  that calls one in another folder says so (`../deliver/run-log.sh`)
- whoever adds a tool adds its row, to the table of the section that holds its
  kind of work; the pre-commit hook refuses a commit that adds any of the
  following unless its name appears on this page or in
  [1.1](https://github.com/delphside/programme/blob/main/docs/1.1-programme-tooling.md#claudes-tooling):
  - a `.sh` or `.py` file in `scripts/`, or an executable file below it
    (except in `tests/`)
  - a file in `.githooks/`
  - a `.claude/*.sh` file
  - a skill folder `.claude/skills/<name>/`
- a tool outside `scripts/` (hooks, `.claude/`, `.github/`, `programme.toml`,
  `e2e/`, cargo binaries) has its row in the table of the section that holds its
  kind of work, though the hook does not check it

## Examples

**An example demonstrates, measures or reproduces, and is not a tool.**

- it has a row only where a document sends the reader to it, as for the two
  examples in *Measure*
- it never writes a file the binary compiles in, because `programme.toml` lists
  `examples/` as not reaching the image; such a generator is a crate
  (`crates/wordlist-tools`)
