# 5.6 Delivery log

This application's delivery log: one row per project delivery, oldest first,
for somebody asking **which planned pieces of work reached their users, when,
and did they work.** It is a programme record
([5.2](5.2-workstreams.md#programme-and-application)). What gets a row, how a
delivery is identified and when the row is written are
[5.1 §2.14](5.1-change-lifecycle.md#the-delivery-log-row-is-part-of-the-delivery);
the columns are [the template](templates/delivery-log.md). Change history is
derived from git, not from here.

**It starts at #174.** Deliveries before 2026-08-22 are recoverable from the
`prod-*` tags and the closed milestones, and are not retrofitted here: a log
back-filled from memory would claim a completeness it does not have.

**A GitHub Release is not this.** `deploy.sh` publishes one per `prod-X.Y.Z`
tag, as the public changelog of *releases*; this log holds *deliveries*,
including those that shipped no code ([3.3](3.3-testing-ci-and-release.md)
§3.3.1).

## What each delivery left behind that git does not show

`0.7.0a` is the first row where most of the change exists only on the host and
in the OCI console. `docs/4.8-artefacts.md` is the register of those; this log
records only that the delivery happened.

**The drill proved more than the restore path.** The two backups either side of the sweep differ by exactly one game — 27 at 18:45, 26 at 03:14 — and the journal names the cause: `terminal game auto-deleted after 7 days`, logged at 20:19:47. A backup that faithfully records a change nobody made by hand is better evidence that it is real than any assertion about it.

**Two defects were found by running it**, both fixed the same evening:

- `sqlite3` was in the server image but not on the host, and the backup's
  integrity check runs on the host. The first real run failed.
- All three marker uploads used `curl -T -`, which sends chunked encoding; OCI
  answers **501**. Since every alarm watches a marker for absence of success,
  not one could ever have been satisfied — #199.

Neither was visible from the repository. Both were found by the delivery's own
step 3, which is the argument for proving a delivery rather than declaring it.
