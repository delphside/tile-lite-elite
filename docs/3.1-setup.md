# Setup

Setting up a development machine, once. Building the production host is in
[3.4](3.4-production-environment.md#building-a-host); every script is in
[3.0 Tools](3.0-tools.md).

## Development environment

The dev machine (WSL2 Ubuntu, treated as disposable) needs a Rust toolchain,
the `wasm32-unknown-unknown` target, `dioxus-cli` and `wasm-bindgen-cli` at the
versions this project uses (a mismatch fails confusingly, see
[Troubleshooting](#troubleshooting)), `sccache`, bats with its two helper
libraries, and Docker Engine with its build cache capped at 20 GB. Under WSL
Docker sizes its limit from the virtual disk rather than the Windows drive, and
without a fixed cap it kept 305 GB.

```bash
git clone https://github.com/delphside/tile-lite-elite.git
cd tile-lite-elite
./scripts/application/develop/setup-dev-environment.sh
```

The script is idempotent, and reads the `wasm-bindgen-cli` version from
`Cargo.lock` rather than hardcoding it. It refuses to run as root; it calls
`sudo` itself for the steps that need it.

**Two steps are manual:**

1. **Restore the deploy SSH key**, `~/.ssh/oracle_tile_lite_elite` and its
   `.pub`, from the copy kept on the Windows side outside WSL. It is a secret,
   so no script fetches it.
2. **Enable systemd in WSL** on a fresh instance, which Docker needs. It is a
   Windows-side change the distro cannot make to itself:

   ```ini
   # /etc/wsl.conf
   [boot]
   systemd=true
   ```

   then `wsl --shutdown` from PowerShell, and reopen the shell. The setup
   script warns if it is missing.

**Verify the result**:

```bash
cargo test --workspace
dx --version                 # should include 0.6.3
docker compose version
bats --version
ssh -i ~/.ssh/oracle_tile_lite_elite ubuntu@129.151.69.246 echo ok
```

## Troubleshooting

### sccache hangs the WASM build

sccache (configured in `.cargo/config.toml`) is incompatible with the `wasm32-unknown-unknown` target. Always set `RUSTC_WRAPPER=""` when building web targets. `scripts/application/develop/services.sh` handles this automatically.

### wasm-bindgen version mismatch

The `wasm-bindgen-cli` version must exactly match the `wasm-bindgen` crate version in `Cargo.lock`. Check with:

```bash
grep -A1 'name = "wasm-bindgen"' Cargo.lock | grep version
```

Then install the matching CLI version:

```bash
cargo install wasm-bindgen-cli --version <version>
```

### reference-types feature required

wasm-bindgen 0.2.103 requires the `reference-types` and `multivalue` WebAssembly proposals to be enabled at compile time. These are set in `.cargo/config.toml`:

```toml
[target.wasm32-unknown-unknown]
rustflags = ["-C", "target-feature=+reference-types,+multivalue"]
```
