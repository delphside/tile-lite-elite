# Client-Local Storage

*Verified against the code at `44c081c` (app 0.9.1, 2026-09-28). To see what has changed since, `git log 44c081c..HEAD -- crates/`; for this document's own history, `git log --follow -- <this file>`.*

Small bits of state the web/desktop client keeps **on the device**, across app
restarts — client preferences, not game data (which is server-owned; see
[4.5 Data Dictionary](4.5-data-dictionary.md)). Derived from
`crates/ui/src/local_storage.rs`.

**Where it's kept differs by platform** (there's no browser `localStorage` on
desktop):

- **Web** — browser `localStorage`, under fixed keys.
- **Desktop** — a small JSON file under the OS config directory
  (`dirs::config_dir()/tile-lite-elite/…`).

Both are best-effort: a failed read falls back to the type's `Default`, and a
failed write is ignored — losing this state only costs a re-login or a reset
unread indicator, never anything the server cares about.

## `StoredAuth`

| Field | Type | Notes |
|---|---|---|
| `remembered_name` | string \| null | Pre-fills the display-name field next time. Pure convenience, no security weight — kept when "Remember me" is checked. |
| `session_token` | string \| null | The bearer token, **only** when "Stay logged in" was checked; otherwise null, and the token is kept transiently (below). The server's expiry is the same either way ([2.5](2.5-authentication.md), [4.2](4.2-database-schema.md#sessions)). |

- Web key: `tile_lite_elite_auth`
- Desktop file: `…/tile-lite-elite/auth.json`

**Without "Stay logged in"**, the token is kept where it survives a reload but
not closing the app:

| platform | where | survives |
| --- | --- | --- |
| web | browser `sessionStorage`, key `tile_lite_elite_session_token` | a reload, including the client reloading itself for a new build; not closing the tab |
| desktop | memory only | nothing beyond the process |

Every login writes both stores, so unchecking the box on a later login leaves
no persistent token behind; logging out, or a token the server refuses, clears
both. On startup the client takes the token from either store
(`load_token`), re-validates it with `POST /auth/validate`, and clears both if
it is no longer valid. "Remember me" keeps `remembered_name` and nothing else; a
rename updates a remembered name, so the next login is pre-filled with the new one.

**Security note:** persisting a bearer token in `localStorage`/a plaintext file
is the usual convenience-vs-exposure trade-off, and is why it's opt-in ("Stay
logged in") rather than the default. Without it, closing the tab drops the
token and the next visit requires a fresh login. The token's exposure window is
bounded by the session's absolute + idle limits regardless (see
[4.2](4.2-database-schema.md#sessions)).

## `StoredChatWatermarks`

| Field | Type | Notes |
|---|---|---|
| `last_seen` | map<game_id, i64> | Per game, the `created_at` (unix seconds) of the newest chat message this device has seen, from any sender. A game shows unread chat when its `last_message_received_at`, the newest message from **another** player, is strictly newer than its entry, or it has no entry (`has_unread_chat`, `games_panel.rs`). Strictly newer, because sending a message and seeing it moves the entry past the last one received. |

- Web key: `tile_lite_elite_chat_seen`
- Desktop file: `…/tile-lite-elite/chat_watermarks.json`

Purely local: there is **no server-side read-receipt concept**, so unread state
is per device/browser and never shared or synced.
