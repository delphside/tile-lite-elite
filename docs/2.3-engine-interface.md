# Engine Interface

How a computer player plugs into the server. An engine chooses a move; the
server validates and applies it exactly as it would a player's. How fast the
engine is, and how that is measured, is [2.8](2.8-engine-performance.md).

## The trait

`crates/engine-core` defines it:

```rust
pub trait GameEngine: Send + Sync {
    fn metadata(&self) -> &EngineMetadata;
    fn choose_action(&self, request: EngineRequest<'_>) -> EngineResponse;
}
```

`choose_action` is synchronous and pure: given a request, it returns an action.
It owns no game state and no rules; it asks `rules-shared` for legal moves and
their scores, like any other client of the rules.

| type | carries |
| --- | --- |
| `EngineRequest` | the board (`GameState`), the seat, its rack, the game's `VariantRules`, and a time budget in milliseconds |
| `EngineResponse` | an `EngineAction` and `EngineDiagnostics` |
| `EngineAction` | `Place(MoveCandidate)`, `Pass`, `Exchange(tiles)` or `Resign` |
| `EngineDiagnostics` | an optional explanation, how many candidates were considered, and the chosen score |
| `EngineMetadata` | id, name, version, author, description, the editions it supports, and capability flags |

**The request carries the game's rules**, and an engine must score and generate
under them rather than rules of its own, or it would misplay every edition but
one.

**The capability flags** (`supports_timed_play`, `supports_analysis`,
`supports_ranking`) are declared and published, and nothing reads them yet.

## How the server runs an engine

A seat of kind `Engine` names an engine by id. When it is that seat's turn,
`GameSession::maybe_run_engine_turn` (`crates/server-game/src/game_state.rs`):

1. finds the engine in the `EngineRegistry`, and refuses if its metadata does
   not list the game's edition;
2. runs `choose_action` on a blocking thread, under a **5-second** limit
   (`ENGINE_TURN_TIMEOUT`, passed in as the request's time budget);
3. auto-passes the seat if the limit is reached, and reports an error if the
   engine panicked;
4. applies the action through the same `apply_place_move`, `apply_pass`,
   `apply_exchange` or `apply_resign` a player's action goes through, so an
   illegal move is refused by the same validation;
5. records the engine's measured compute time on the move.

`run_engine_turns` repeats this while the current seat is an engine, up to
`MAX_ENGINE_TURNS_PER_TRIGGER` (400) per request, broadcasting after each turn
and pausing `ENGINE_TURN_BROADCAST_DELAY` (120 ms) so the moves can be seen. At
most `TILE_LITE_ELITE_ENGINE_CONCURRENCY` searches run at once
([4.1](4.1-configuration.md)).

The engine runs in-process and is not sandboxed from the server
([1.3](1.3-technology-decisions.md)). #71 moves it towards being a client of the
public API, like any other player.

## The engines

`GET /engines` lists the registered engines' metadata as `EngineProfileDto`
([4.3](4.3-api-schema.md)). There is one:

**Greedy** (`greedy-v1`) plays the highest-scoring legal move it finds, and
passes when there is none. It never exchanges or resigns. It declines any move
forming a greylisted word, main or cross word
([3.5](3.5-word-lists-and-dictionaries.md)), checking only a move about to
become its best so far. It lists every edition, retired ones included, so a
bot seated in an old game is never stranded.

A change that makes a bot play differently is a new engine with a new id, not
a change to Greedy.

## Versioning an engine

An engine carries a version in its metadata, and an id that names it. There is
no separate version for the interface itself: the trait is compiled into the
server with every engine, so the two cannot disagree.

## Testing

`crates/engine-core`'s tests hold the engine's choices against injected word
lists: a move forming an avoided word is declined, cross words included, and
the next best is played instead. The server's tests
(`crates/server-game/src/app/tests.rs`) drive engines through the API: an
engine replying to a player's move, and engine-against-engine games running to
completion. The timing benchmark plays whole games through the same path
([2.8](2.8-engine-performance.md)).
