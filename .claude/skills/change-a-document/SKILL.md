# Changing a document

**Read this before adding text to anything in `docs/`.** Not after.

## Why it exists

`one fact, one home` is a rule about where a fact belongs, and it is unusable
without knowing all the homes. There are **~530 sections across 31 documents**
and no one person's head holds them, so the practical question *"where does this
go?"* was being answered with *"where I already am"*.

Four facts went into the wrong place on 2026-09-07, three of them caught by the
owner rather than by anything here (#349).

## The procedure

Owner, 2026-09-07: *"for any change you should be able to identify the section
which covers it, and read that section before making changes. If the correct
section cannot be found then either there is something wrong with the map, with
the document structure, or there is a gap in the documents. You should search to
find if it is somewhere else."*

**1 · Name the subject.** Not the file you are in — the *thing the sentence is
about*. "e2e only runs on some branches" is about CI triggers, wherever you
happen to have noticed it.

**2 · Find its section in [`docs/1.6-document-map.md`](../../../docs/1.6-document-map.md).**
Generated by `scripts/document-map.py`, so it is never stale.

**3 · Read that section before writing.** Most of the time the fact is already
there, or half there, and the change is an edit rather than an addition. This is
the step that was being skipped.

**4 · If you cannot find the section, that is a finding — do not fall back to
writing it where you are.** Search the documents properly (`grep -ri` on the
subject's words, not yours). Then say which of these it is:

| | what it means | what to do |
| --- | --- | --- |
| **the map is wrong** | the section exists and the map does not show it | a defect in `document-map.py` — fix it |
| **the structure is wrong** | it exists but under a heading nobody would look for | rename or move the section, and say so in the commit |
| **there is a gap** | genuinely nothing owns this subject | create the section in the document that *should* own it, and say why in the commit |

**Never a fourth outcome.** "I could not find it so I put it here" is what this
whole procedure exists to prevent.

| `1.0-rules` | how the game behaves — the rules themselves |

| `3.3-testing-ci-and-release` | verifying a change and shipping it: the steps, the flavours, CI, the environments, deploy, rollback |

| `4.2` · `4.4` · `4.5` | schema, snapshot JSON, and where each field lives |
| `4.3-api-schema` | every endpoint and wire type, and its errors |

**The argument goes in the issue; the conclusion goes in the document.** A
document says what is true now, not how it was decided.

**A project body links, it does not restate.** `raise-project`: *the content or
a link to the design document that holds it, never both*.

## Traps that have actually cost time

**Renumbering breaks anchors, and the link checker only catches the linked
ones.** `docs/3.3` carried two `§2.13.2`s for weeks; it surfaced because
something happened to link to one. Renumber only with `document-map.py --check`
and the link check both green.

**A `.svg` in `docs/diagrams/` has a `.mmd` beside it.** Edit the source and
re-render — `docs/diagrams/README.md` has the command and the Puppeteer failure
to expect. Editing the SVG is editing a build output.

**A semicolon ends a mermaid statement.** `(Bearer token; wasm only)` broke a
sequence diagram for 39 days and rendered as an error box, invisible to every
check. Inline mermaid is checked by nothing today (#340).

**`docs/3.3` numbers three levels and only two are headings.** `1.2` is a
section; `1.2.3` is an arrow in a diagram and has no heading, deliberately.

**Two branches can both add `§2.5.1`.** `document-map.py` catches it once they
meet; before that, check what is in flight.

## Afterwards

```bash
./scripts/check-docs.sh                 # lint, links, placement
./scripts/document-map.py --write       # regenerate, and report duplicates
```

**Commit the regenerated map.** It is derived, so it must not sit stale in the
working tree — the same rule as `docs/1.5`.

## What goes wrong

**Writing the same thing in two places.** On 2026-09-07 the `paths:`
explanation went into `§2.5` *and* `§2.5.2`, and a flavours table was added
forty lines above an existing table answering the same question. Both were
found by the owner reading it, which is the expensive way.

**Preferring the open page.** This is about effort, not information: the map
tells you where the fact belongs, and going there is still more work than
typing it here. The procedure above is the counterweight, and step 4 is the
part that makes not-finding-it cost something.
